# FareRadar V1.4 Hardening Audit Delta

本檔只記錄 V1.4 hardening 相對 V1.3 baseline 的稽核增量。每個 wave 固定使用：

`Finding -> Evidence -> External Baseline -> Patch -> Regression -> Provider Readback -> Residual Risk`

## Wave 1 - Supply chain and durable Gate evidence

### Finding

- CI Gate artifact retention 僅 14 天。
- Repository 尚未設定 Dependabot、dependency review、CodeQL。
- exact-head Gate evidence 尚無 compact manifest 綁定 CI run 與 artifact digest。

### Evidence

- baseline: `main@8c108c0ac2bf10e4d652d09dd2a473d7349ff020`
- exact-head CI baseline: run `35290792602` = `success`
- baseline `.github/workflows/ci.yml`: `retention-days: 14`
- baseline `.github/dependabot.yml`: absent
- baseline dependency-review / CodeQL workflows: absent

### External Baseline

- GitHub Actions third-party actions must stay full-SHA pinned.
- Dependency review executes only on pull requests with least-privilege `contents: read`.
- CodeQL starts advisory/non-blocking and is not a required Production Gate in this wave.

### Patch

- Add Dependabot for `github-actions`, `npm`, and `pip`.
- Add PR dependency review pinned to exact action SHA, failing on high-or-higher vulnerable dependency introduction.
- Add advisory CodeQL for JavaScript/TypeScript and Python pinned to exact action SHA.
- Raise Gate evidence retention to 90 days.
- Add compact release evidence manifest with exact commit/spec/dependency/test hashes, 37-Gate summary, CI run ID, and Gate artifact ID/digest.

### Regression

Required static/regression coverage:

- workflow action refs remain immutable SHA pins;
- workflow permissions stay least-privilege;
- both evidence artifacts retain 90 days;
- manifest fails closed unless 37/37 + full-suite PASS;
- Dependabot covers all three ecosystems;
- dependency review is PR-only and fail-on-severity is `high`;
- CodeQL remains advisory until a later promotion decision.

### Provider Readback

Pending until branch exact-head CI finishes. Main branch protection and Cloudflare provider state are separate P0 provider Gates and are not satisfied by this wave.

### Residual Risk

- GitHub `main` protection is still a provider-side Critical blocker until an Administration-write path applies and reads it back.
- Cloudflare/D1 same-session provider truth and least-privilege token scope still require provider readback.
- Artifact Attestation/SBOM remain P2 and are not Production blocking yet.


## Wave 2 - D1 recovery and Cloudflare credential boundary

### Finding

- Worker rollback is version-only; D1 requires an independent recovery contract.
- Production migrations previously lacked pre-migration Time Travel bookmark evidence and an explicit destructive-schema denylist.
- Cloudflare Production preflight did not require proof that steady-state credentials were resource-scoped and non-Admin.

### Evidence

- V1.3 Production deploy reports `WORKER_VERSION_ONLY_D1_NOT_ROLLED_BACK`.
- Baseline provisioning reconciles uncertain migration responses by reading `d1_migrations`, but did not preserve a Time Travel bookmark.
- Baseline preflight accepted Cloudflare auth/readback without a separate credential-scope artifact.

### External Baseline

- Cloudflare D1 Time Travel provides current bookmarks and destructive point-in-time restore.
- Current Developer Platform permissions support account-owned API tokens scoped to an individual Worker with `Editor`; Editor can deploy/update but cannot create/delete the Worker.
- Granular Wrangler authorization requires an account-owned API token.

### Patch

- Capture D1 Time Travel bookmark before any pending Production migration.
- Persist before/pending/after migration recovery evidence.
- Block `DROP TABLE`, `DROP COLUMN`, and table/column rename in the same Production release.
- Keep D1 restore as a separate plan-first, exact-bookmark human Gate.
- Assert Worker rollback never invokes D1 restore.
- Add Production blocker `CLOUDFLARE_CREDENTIAL_SCOPE_EVIDENCE_MISSING`.
- Require same-session credential evidence showing bootstrap inactive, Worker deploy = account-owned token + individual `fare-radar` scope + Editor + no delete, and D1 admin credential limited to `fare-radar-production`.

### Regression

- destructive migration negative corpus;
- expand-only positive corpus;
- bookmark/readback evidence;
- lost migration response reconciles exactly once;
- D1 restore defaults to plan-only and cannot execute without exact human-approved bookmark;
- Worker rollback source contains no D1 Time Travel restore path;
- local token environment cannot satisfy credential-scope evidence;
- Worker Admin/delete-capable or active bootstrap credential fails preflight.

### Provider Readback

Pending. This workspace currently has no usable Cloudflare account connector, so no live Cloudflare credential or D1 readback is claimed.

### Residual Risk

- Live token policy/resource scope still requires same-source Cloudflare evidence.
- Existing credentials, if broader than this contract, must be rotated/revoked at the provider before V1.4 Production PASS.
- D1 restore remains destructive and human-reserved by design.
